# Oracle-labeled corpus

**Status:** proposed, not started. Open decisions are marked **Decide**.

The Teaching trust level (`docs/VERIFICATION.md`, "Trust levels") needs an
oracle-labeled corpus, and reference cores that match Icarus Verilog by VCD on
Linux, macOS and Windows. Neither exists. Every test today is SystemVerilog
embedded in a C++ doctest, compared against a string its author wrote, with no
record of where that string came from, and no comparison covers anything a test
does not print.

## What the corpus is for

- **Evidence that values are right.** A case is evidence only if its expected
  result did not come from Clotho (VERIFICATION.md, "Oracles"). Every case names
  its oracle.
- **Everything observable is compared**, not only stdout: VCD per time step per
  signal.
- **One runner** checks a case under every semantics-preserving configuration,
  so a case with no external expected output is still a self-consistency test.
- **The landing place** for reduced fuzzer and crash findings, which today
  become ad hoc doctests.

## Layout

One directory per case:

```
tests/corpus/<clause>/<case>/
  case.toml       # metadata, below
  design.sv       # plus any other sources the case lists
  expected.out    # stdout, when the oracle supplies one
  expected.vcd    # normalized VCD, when the oracle supplies one
```

`<clause>` is the LRM clause the case is mainly about (`11.4.5`, `9.4`), which
is what the "Sections" bar in VERIFICATION.md counts over. A case touching
several clauses lists the others in `case.toml`.

`case.toml` reuses the shape of `tests/perf/cases/*/case.toml` where it can:

```toml
top = "tb"
files = ["design.sv"]
clauses = ["11.4.5", "7.2"]
oracle = "icarus"            # lrm | icarus | metamorphic | self | snapshot
oracle_note = "iverilog 13.0, regen-icarus.py"
stop_time = "10us"           # bound for free-running designs
dump = ["tb.dut"]            # $dumpvars scopes the runner injects
configs = "all"              # or a subset, with a reason
```

## Oracles

| label | expected output | written by |
|---|---|---|
| `lrm` | `expected.out` / `expected.vcd` written from the LRM | an author independent of the implementation (VERIFICATION.md, "Writing tests") |
| `icarus` | generated by a pinned Icarus Verilog, then committed | `tests/corpus/regen-icarus.py`; the version is recorded per case |
| `metamorphic` | none; the case names a sibling case whose output must be identical | the case author, stating the rewrite (commuted operands, flattened hierarchy, a packed struct replaced by its vector) |
| `self` | none; only the configurations must agree | anyone |
| `snapshot` | Clotho's own earlier output | a regression guard, never counted as evidence |

**Decide (1): commit Icarus goldens, or run Icarus in CI.** CI installs no
iverilog. Committing generated goldens keeps every platform's job oracle-free and
deterministic, and pins the oracle version. The cost is regenerating on an Icarus
upgrade, and goldens that can go stale against the design if the generator isn't
rerun; the runner refuses a case whose `design.sv` hash differs from the hash
recorded when its golden was generated. Running Icarus live needs an install step
on six platforms (MSYS2 and Homebrew both package it [INFERENCE, unverified]).
Proposal: commit goldens.

## Configurations

Every case runs under each configuration below. The outputs must be identical to
each other, and to the expected files when the oracle supplies them:

- `run`, default tier;
- `run -O`;
- `build`, then the executable;
- the in-process `SimulationConfig` gates `check_all_lowerings` already varies
  (`tests/comb_fusion_test.cpp:52`: `thunk=false`; `fuse=false, thunk=false`);
- `--gc-stress`, for a case that allocates class objects.

The CLI does not expose the `SimulationConfig` gates.

**Decide (2): runner language.** Proposal: C++ inside `clotho_test`, one ctest
entry per clause directory. It runs on all six CI platforms with no new
dependency, reaches the in-process gates directly as `check_all_lowerings` does,
and drives `build` through the CLI as `tests/cli_test.cpp` does. A Python runner
in the style of `tests/perf/perf.py` would be quicker to write but needs Python
on every platform, plus new CLI flags for the gates.

## Comparing VCD

The runner injects `$dumpfile` / `$dumpvars` for the scopes in `dump`, the way
`tests/vcd_test.cpp` rewrites `OUT.vcd`. Comparison is on a normalized form:

- **Signals by name.** Signals are keyed by full hierarchical name; id codes,
  header, scope and var order are ignored.
- **Values sampled per time step.** Each signal's value is compared at the end
  of every time step at which either side records a change. Changes within one
  time step are not compared: their order is not fixed (LRM 4.7), and Icarus
  emits glitches Clotho may legally not.
- **Values exact,** x and z included.
- **One known Icarus divergence is normalized away:** Icarus pulses every event
  variable at time 0, at `$dumpall` and at `$dumpon`, which is wrong
  (`tests/vcd_test.cpp:654-659`). Event variables compare only at real triggers.

A mismatch reports the first differing time step and signal.

## Known disagreements

`tests/corpus/known.txt`, in the format of `.github/scripts/sv-tests-known.txt`:
`<category> <case> <reason>`, where the categories are:

- `oracle`: Icarus contradicts the LRM, citing a `docs/LRM_NOTES.md` note;
- `race`: the output rests on an order LRM 4.7 leaves open; avoid adding these at
  all;
- `gap`: Clotho refuses the case, naming a `docs/TODO.md` entry. The runner checks
  that the refusal's diagnostic names that construct.

An entry whose case now passes, or fails in a different way, fails the run until
it is removed: the same rule as the sv-tests job, so the list cannot rot.

## Reference cores

`tests/perf/cases/` already pins picorv32 (`87c89acc`), hazard3 (`8af99293`) and
cv32e40p (`6033d2b1`) with fetch scripts and testbenches. The corpus reuses those
fetch scripts and pins. Each core case runs a bounded firmware (hazard3's
checksum firmware, picorv32's 16-instruction one), dumps the core's top-level
ports and register-file writes rather than the whole hierarchy, and ends at a
fixed `stop_time`, so the golden VCD stays small.

**Decide (3): fetch or vendor.** Fetching at the pinned commit (with a CI cache)
keeps third-party sources out of the repo. Vendoring removes the network
dependency, but needs the licenses checked first: picorv32 ISC, Hazard3
Apache-2.0, cv32e40p Solderpad, all [INFERENCE, unverified]. Proposal: fetch.

## CI

- **Every push (linux-x64):** the ctest entries; all oracles are committed files.
- **`main`, `ci/*`, nightly:** the same on all six platforms. The Teaching bar is
  this job green on Linux, macOS and Windows, cores included.
- **Not in CI:** `regen-icarus.py`, run locally when a case or the Icarus pin
  changes.

## Phases

| # | scope | done when |
|---|---|---|
| 1 | runner, `case.toml`, known list, the configuration matrix, stdout comparison; ~20 seed cases moved from doctests whose expected values are already labeled "Icarus 13" in their comments | the cases pass on linux-x64 in ctest |
| 2 | VCD injection and normalized comparison; `regen-icarus.py` with the hash check | an Icarus-golden VCD case passes, and a deliberately changed design fails its hash check |
| 3 | picorv32 and hazard3 core cases | both match their Icarus goldens on linux-x64 |
| 4 | all six platforms on `main` / nightly | green on Linux, macOS and Windows |

Afterwards, new SystemVerilog-level tests for behavior land here rather than as
doctests (VERIFICATION.md, "Writing tests"), and fuzzer findings land here once
reduced.

## Not in scope

- The differential fuzzer itself (a separate design). The corpus is where its
  reduced findings land.
- Moving existing doctests wholesale. Only the seed cases move. Others move when
  they are touched, if they compare output rather than an internal invariant.
- Verilator as an oracle; event semantics differ (`docs/PRINCIPLES.md`).
